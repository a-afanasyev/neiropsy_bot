# Диагностика проблем с Docker Compose

## Проблема: Запускается только 2 контейнера вместо 3

Если запускается только `app` и `db`, но не запускается `redis`, это нормально - Redis опционален.

### Проверка статуса контейнеров

```bash
# Проверить статус всех контейнеров
docker-compose ps

# Проверить логи Redis (если он не запускается)
docker-compose logs redis

# Проверить, занят ли порт 6380
netstat -tuln | grep 6380
# или
lsof -i :6380
```

### Решения

#### Вариант 1: Запустить без Redis (рекомендуется для начала)

Приложение может работать без Redis, используя in-memory хранилище. Просто запустите:

```bash
docker-compose up -d app db
```

Или закомментируйте сервис redis в `docker-compose.yml`:

```yaml
  # redis:
  #   image: redis:7-alpine
  #   ...
```

И уберите REDIS_URL из переменных окружения app (или оставьте пустым).

#### Вариант 2: Исправить проблему с Redis

Если порт 6380 занят другим сервисом:

1. Измените внешний порт Redis в `docker-compose.yml`:
```yaml
ports:
  - "6381:6379"  # Используйте другой свободный порт
```

2. Или используйте существующий Redis на сервере:
```yaml
environment:
  - REDIS_URL=redis://localhost:6379/0  # Используйте внешний Redis
```

#### Вариант 3: Проверить логи и исправить ошибки

```bash
# Посмотреть логи всех сервисов
docker-compose logs

# Посмотреть логи конкретного сервиса
docker-compose logs redis
docker-compose logs app

# Перезапустить проблемный сервис
docker-compose restart redis
```

### Проверка работы приложения без Redis

Приложение автоматически переключится на in-memory хранилище, если Redis недоступен. В логах вы увидите:

```
Redis URL не задан, используем in-memory хранение
```

или

```
Не удалось подключиться к Redis: [ошибка]
Используем in-memory хранение
```

**Важно:** При использовании in-memory хранилища:
- Состояния сессий теряются при перезапуске контейнера
- Нельзя масштабировать приложение на несколько инстансов
- Для production рекомендуется использовать Redis

### Проверка работоспособности

```bash
# Проверить health check API
curl http://localhost:8088/health

# Проверить логи приложения
docker-compose logs -f app

# Должны увидеть:
# ✅ Redis подключен для хранения состояний
# или
# Redis URL не задан, используем in-memory хранение
```
