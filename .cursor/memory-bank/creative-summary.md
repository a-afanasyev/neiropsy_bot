## 🎯 КЛЮЧЕВЫЕ АРХИТЕКТУРНЫЕ РЕШЕНИЯ

### 1. Схема БД

**Решение**: Гибридный подход
- Новые таблицы для логики батчей
- Переиспользование таблицы `responses` для ответов
- Связь через `batch_responses` (many-to-many)

**Преимущества**:
- Минимальные изменения существующего кода
- Безопасность рабочих данных
- Легко откатить, если что-то пойдет не так

---

### 2. API Design

**Решение**: RESTful endpoints с префиксом `/batches` и `/batch-sessions`

**Преимущества**:
- Совместимость с существующими endpoints
- Понятная структура
- Легко расширять

---

### 3. Telegram Bot Flow

**Решение**: Расширение существующей логики прохождения

**Ключевые элементы**:
- Проверка типа сессии через префикс токена (`batch_`)
- Inline keyboard с чекбоксами для выбора
- Прогресс-бары для мотивации
- Автоматическое сохранение прогресса

**Преимущества**:
- Знакомый UX для пользователей
- Минимальные изменения в bot.ts
- Понятные сообщения

---

### 4. Алгоритм агрегирования

**Решение**: Простая конкатенация + правила на основе ключевых слов

**Не требует**:
- ML или сложной аналитики
- Внешних библиотек
- Обучения моделей

**Преимущества**:
- Простой, понятный код
- Предсказуемые результаты
- Легко расширять правила
