# ДЕТАЛЬНОЕ ПРОЕКТИРОВАНИЕ: Система батч-опросников

**Дата**: 2025-11-06  
**Уровень**: Level 3 (Feature Development)

---

## 1️⃣ PROBLEM (Проблема)

### Что проектируем?

Систему, которая позволяет специалисту создавать наборы из нескольких опросников (батчи), генерировать одну ссылку для прохождения всех опросников последовательно, и получать агрегированный отчет по всем результатам.

### Требования

**Функциональные:**
- Специалист выбирает 2-10 опросников через Telegram бота
- Генерируется одна ссылка с токеном для всего батча
- Пользователь проходит опросники последовательно (1→2→3→4)
- Прогресс сохраняется после каждого вопроса
- После завершения генерируется агрегированный отчет
- Специалист получает уведомление и отчет
- Доступна выгрузка в JSON и CSV

**Технические:**
- Новая схема БД с 5 таблицами
- REST API endpoints для управления батчами
- Расширение Telegram бота для работы с батчами
- Алгоритм агрегирования множественных результатов
- Поддержка существующей логики (обратная совместимость)

**Ограничения:**
- Максимум 10 опросников в одном батче
- Токен действителен 48 часов (увеличено с 24)
- Простой, понятный код (принцип проекта)
- Сохранение рабочих данных в существующей БД

## 2️⃣ OPTIONS (Варианты)

### Вариант A: Новые таблицы с полной изоляцией

**Описание**: Создать полностью независимые таблицы для батчей, не изменяя существующие.

**Плюсы:**
- ✅ Нулевой риск для существующего функционала
- ✅ Легко откатить изменения
- ✅ Простая разработка и тестирование

**Минусы:**
- ❌ Дублирование некоторой логики
- ❌ Больше кода для поддержки

**Сложность**: Средняя

### Вариант B: Расширение существующих таблиц

**Описание**: Добавить поля в существующие таблицы (sessions, responses).

**Плюсы:**
- ✅ Меньше таблиц
- ✅ Единая логика

**Минусы:**
- ❌ Риск нарушить существующий функционал
- ❌ Сложнее тестировать
- ❌ Необходимость миграции данных

**Сложность**: Высокая

### Вариант C: Гибридный подход (выбранный)

**Описание**: Новые таблицы для батчей + использование существующей таблицы responses для хранения ответов.

**Плюсы:**
- ✅ Баланс между изоляцией и переиспользованием
- ✅ Минимальные изменения существующего кода
- ✅ Ответы хранятся единообразно
- ✅ Легко выгружать данные

**Минусы:**
- ❌ Нужна связующая таблица (batch_responses)

**Сложность**: Средняя

## 4️⃣ DECISION (Решение)

### Выбранный подход: Вариант C (Гибридный)

**Обоснование:**
- Максимальная безопасность для рабочих данных (2 ответа в БД)
- Простота разработки и тестирования
- Хорошее переиспользование существующих компонентов
- Легко откатить, если что-то пойдет не так

### Ключевые архитектурные решения:

#### 1. Схема БД
- 5 новых таблиц: `questionnaire_batches`, `batch_questionnaires`, `batch_sessions`, `batch_responses`, `batch_reports`
- Таблица `responses` используется для хранения всех ответов (и одиночных, и батчевых)
- Связь через `batch_responses` позволяет отследить порядок и принадлежность к батчу

#### 2. API Design
- RESTful endpoints с префиксом `/batches` и `/batch-sessions`
- Совместимость с существующими endpoints
- Отдельные endpoints для выгрузки батчевых отчетов

#### 3. Telegram Bot Flow
- Новая команда `/newbatch` для создания
- Inline keyboard с чекбоксами для выбора опросников
- Расширение существующей логики прохождения (`handleMessage`)
- Проверка типа сессии (обычная vs батч) через префикс токена

#### 4. Алгоритм агрегирования
- Последовательная обработка результатов каждого опросника
- Сбор всех баллов, уровней и флагов
- Генерация текстового резюме на основе правил
- Формат отчета: секции по опросникам + общие выводы

## 5️⃣ IMPLEMENTATION NOTES (Руководство по реализации)

### A. Миграция БД (006_add_batch_questionnaires.sql)

#### Создать таблицы в следующем порядке:

1. **questionnaire_batches** - основная таблица батчей
2. **batch_questionnaires** - связь с опросниками (с order_index)
3. **batch_sessions** - токены для батчей
4. **batch_responses** - связь ответов с батчами
5. **batch_reports** - агрегированные отчеты

#### Ключевые особенности:

- Все FK с `ON DELETE CASCADE` для автоматической очистки
- Индексы на все FK и часто используемые поля
- Уникальные ограничения для предотвращения дублей
- Триггеры для `updated_at` через существующую функцию

### B. TypeScript типы (types.ts)

#### Добавить интерфейсы:

```typescript
// Основные типы батчей
QuestionnaireBatch
BatchQuestionnaire  
BatchSession
BatchResponse
BatchReport

// Расширенное состояние пользователя
BotUserBatchState extends BotUserState
```

#### Ключевые поля:

- `order_index` - для последовательности опросников
- `completed` - флаг завершения батча
- `aggregated_scores_json` - агрегированные результаты

### C. Репозиторий (repo.ts)

#### Группы методов:

1. **Батчи** - CRUD для questionnaire_batches
2. **Батч-сессии** - создание, проверка токена, завершение
3. **Батч-ответы** - связь responses с батчами
4. **Батч-отчеты** - создание и получение отчетов
5. **Состояние пользователя** - расширение для батчей

#### Важные методы:

- `getBatchSessionByToken()` - проверка токена с join для загрузки батча
- `getBatchQuestionnairesOrdered()` - получение опросников в правильном порядке
- `completeBatchSession()` - атомарное завершение с транзакцией

### D. REST API (server.ts)

#### Endpoints:

```
POST   /batches                          - Создать батч
GET    /batches/:id                      - Получить батч
POST   /batch-sessions                   - Создать сессию
GET    /batch-sessions/:token            - Проверить сессию
GET    /batch-reports/:batch_session_id  - Получить отчет
GET    /exports/batch-report/:id.json    - Выгрузка JSON
GET    /exports/batch-report/:id.csv     - Выгрузка CSV
```

#### Особенности:

- Валидация через Zod схемы
- Проверка прав доступа (только создатель батча)
- Обработка ошибок с понятными сообщениями

### E. Telegram Bot (bot.ts)

#### Новые команды:

1. **`/newbatch`** - создание батча
   - Показать список опросников
   - Inline keyboard с чекбоксами
   - Обработка через callback_query

2. **`/start batch_{token}`** - начало батча
   - Проверка токена
   - Загрузка батча и опросников
   - Начало первого опросника

3. **`/batchreport {id}`** - получение отчета
   - Только для создателя батча
   - Форматирование отчета
   - Кнопки для выгрузки

#### Изменения в существующей логике:

- `handleStart()` - определение типа токена (session vs batch)
- `handleMessage()` - проверка типа состояния (обычное vs батч)
- `loadUserState()` - поддержка батч-состояния

#### UX элементы:

- Прогресс-бар: "📝 Опросник 2 из 4"
- Мотивация: "✅ Опросник 1 завершен! Переходим к следующему"
- Благодарность: "🎉 Все опросники завершены!"

### F. Scoring (scoring.ts)

#### Новая функция агрегирования:

```typescript
function aggregateBatchScores(
  responses: Array<{
    questionnaire: Questionnaire;
    response: Response;
  }>
): {
  summary: string;
  aggregatedScores: Record<string, any>;
  flags: string[];
}
```

#### Алгоритм:

1. Собрать результаты каждого опросника
2. Извлечь ключевые баллы и уровни
3. Собрать все флаги (warnings)
4. Сгенерировать текстовое резюме:
   - Секция по каждому опроснику
   - Общие выводы на основе паттернов
   - Рекомендации

#### Правила генерации выводов:

- Если 2+ опросника показывают "высокий риск" → общий вывод о необходимости обследования
- Если есть флаги по одной теме (напр. "внимание") → выделить в выводах
- Если результаты противоречивые → отметить необходимость уточнения
