# 📋 ПЛАН РАЗРАБОТКИ: Telegram-бот для батч-опросов

**Дата создания**: 2025-11-06  
**Сложность проекта**: Level 4 (Enterprise Development)  
**Оценка времени**: 26-37 часов

---

## 🎯 ЦЕЛЬ ПРОЕКТА

Создать монолитное приложение на Node.js + TypeScript, которое объединяет:
- Telegram-бот для проведения психологических опросов в батчевом формате
- REST API для управления батчами и получения результатов
- Автоматическую агрегацию результатов и генерацию отчетов

---

## 🛠️ ТЕХНОЛОГИЧЕСКИЙ СТЕК

### Backend
- **Runtime**: Node.js 18+ LTS
- **Язык**: TypeScript 5.x
- **Фреймворк**: Express.js 4.x
- **Telegram**: Telegraf 4.x (современная, хорошо поддерживаемая библиотека)

### База данных
- **СУБД**: PostgreSQL 15
- **ORM**: Prisma 5.x (TypeScript-first, удобные миграции, кодогенерация)
- **Миграции**: Prisma Migrate

### State Management
- **Cache/State**: Redis 6.x (опционально, для production)
- **Fallback**: In-memory Map (для development/MVP)

### Валидация и утилиты
- **Валидация**: Zod (TypeScript-native схемы)
- **Логирование**: Winston (структурированное логирование)
- **HTTP клиент**: Axios (для внешних API если нужно)
- **Экспорт CSV**: json2csv

### Тестирование
- **Framework**: Jest
- **Coverage**: Jest coverage
- **E2E**: Supertest для API
- **Mocks**: Jest mocks для Telegram API

### DevOps
- **Контейнеризация**: Docker + Docker Compose
- **Переменные окружения**: dotenv
- **Форматирование**: Prettier
- **Линтинг**: ESLint + TypeScript ESLint

## 📊 СХЕМА БАЗЫ ДАННЫХ

### Таблицы (7 штук)

#### 1. questionnaires
Хранение шаблонов опросников
```prisma
model Questionnaire {
  id             String   @id @default(uuid())
  title          String
  questions_json Json     // Вопросы опросника
  scoring_json   Json     // Правила подсчета баллов
  created_at     DateTime @default(now())
  updated_at     DateTime @updatedAt
}
```

#### 2. responses
Индивидуальные результаты прохождения одного опросника
```prisma
model Response {
  id           String   @id @default(uuid())
  session_id   String?
  answers_json Json     // Ответы пользователя
  score_json   Json     // Рассчитанные баллы
  summary_text String?  // Текстовое резюме
  created_at   DateTime @default(now())
}
```

#### 3. questionnaire_batches
Батчи опросников
```prisma
model QuestionnaireBatch {
  id                     String   @id @default(uuid())
  title                  String
  created_by_telegram_id BigInt
  is_active              Boolean  @default(true)
  created_at             DateTime @default(now())
}
```

#### 4. batch_questionnaires
Связь батча и опросников (упорядоченный список)
```prisma
model BatchQuestionnaire {
  id               Int          @id @default(autoincrement())
  batch_id         String
  questionnaire_id String
  order_index      Int          // Порядок в батче (1, 2, 3...)
}
```

#### 5. batch_sessions
Сессии прохождения батча
```prisma
model BatchSession {
  id           String    @id @default(uuid())
  batch_id     String
  token        String    @unique  // batch_<random>
  expires_at   DateTime
  completed    Boolean   @default(false)
  completed_at DateTime?
  created_at   DateTime  @default(now())
}
```

#### 6. batch_responses
Связь сессии с ответами на опросники
```prisma
model BatchResponse {
  id                Int    @id @default(autoincrement())
  batch_session_id  String
  questionnaire_id  String
  response_id       String
  order_index       Int
}
```

#### 7. batch_reports
Агрегированные отчеты
```prisma
model BatchReport {
  id                 String   @id @default(uuid())
  batch_session_id   String   @unique
  summary_text       String   // Текстовый отчет
  aggregated_scores  Json     // Агрегированные баллы
  flags_json         Json     // Флаги/метки
  created_at         DateTime @default(now())
}
```

## 🔄 FSM: Состояния батч-сессии

```
┌─────────────────────────────────────────────────┐
│                  FSM Diagram                    │
└─────────────────────────────────────────────────┘

     START
       │
       ▼
  ┌─────────┐
  │ CREATED │  Сессия создана, токен выдан
  └────┬────┘
       │ /start batch_token
       ▼
┌──────────────┐
│ IN_PROGRESS  │  Пользователь проходит опросники
└──────┬───────┘
       │ (Опросники 1...N)
       │ последний ответ получен
       ▼
┌──────────────┐
│  COMPLETED   │  Все опросники завершены
└──────┬───────┘
       │ отчет сгенерирован
       ▼
┌──────────────┐
│   REPORTED   │  Администратор уведомлен
└──────────────┘
```

**Обработка исключений**:
- Истечение срока (expires_at) → отказ при запуске
- Отмена пользователем → незавершенная сессия
- Прерывание → состояние сохраняется (Redis/memory)

## ⚠️ РИСКИ И МИТИГАЦИЯ

### Риск 1: Сложность FSM логики
**Вероятность**: Средняя  
**Влияние**: Высокое  
**Митигация**: 
- Использовать проверенную библиотеку (xstate) или простую реализацию
- Детальное тестирование всех переходов
- Логирование всех изменений состояния

### Риск 2: Интеграция с Telegram API
**Вероятность**: Низкая  
**Влияние**: Среднее  
**Митигация**:
- Использовать Telegraf (хорошо документирована)
- Обработка всех ошибок API
- Retry логика для сетевых проблем

### Риск 3: Потеря состояния при перезапуске
**Вероятность**: Средняя (без Redis)  
**Влияние**: Среднее  
**Митигация**:
- Использовать Redis для production
- Документировать ограничения in-memory режима
- Сохранять прогресс в БД периодически

### Риск 4: Производительность при большом количестве вопросов
**Вероятность**: Низкая  
**Влияние**: Низкое  
**Митигация**:
- Индексы в БД на часто используемых полях
- Lazy loading вопросов
- Кэширование опросников
